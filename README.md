# Telegram Helper — суперанализ диалога

Личный Telegram-клиент на GramJS. По явной команде **владельца аккаунта** читает историю выбранного личного чата и отправляет туда содержательный разбор на русском. Никаких ответов от обычного «хз», скрытых подколов, психотипирования или заранее заданных обвинений.

## Одна команда

В нужном личном чате напиши:

```text
суперанализ
```

Или укажи цель:

```text
суперанализ: хочу понять, стоит ли продолжать романтическое общение
```

**Отчёт публикуется в том же чате, собеседник его видит.** Команды собеседника и сообщения в группах не запускают анализ. Владелец определяется по текущей Telegram-сессии, не по изменяемому username. Без `TG_TARGET` команда работает в личных чатах владельца; можно ограничить список настройкой.

В отчёте:

- наблюдаемая роль и вклад каждого участника, а не выдуманное «всё о человеке»;
- взаимность, инициатива, поддержка, границы, договорённости;
- конфликты, восстановление контакта и изменения по ходу истории;
- сильные стороны и риски с короткими точными цитатами, датами и ID сообщений;
- условный вывод «стоит ли продолжать» относительно твоей цели, аргументы за и против, альтернативные объяснения;
- конкретные следующие шаги, вопросы собеседнику и границы уверенности.

Скрипт проверяет, что цитаты действительно содержатся в исходных сообщениях. При разборе части модель может выбирать только ID сообщений этой части. Это **не** доказывает автоматически правильность интерпретации. Он не ставит диагнозы, не определяет MBTI, не выдаёт молчание за доказательство чувств и не подсказывает манипулятивные «проверки».

Если модель лишь заменила переносы строк или пробелы, скрипт может восстановить их из единственного точно совпадающего фрагмента того же сообщения. Слова, пунктуация, автор и отрицания не исправляются «по смыслу»; неоднозначные или выдуманные цитаты по-прежнему останавливают анализ. На этапе объединения цитата также должна входить в переданный модели конспект.

## Как контролируются расходы

1. История загружается до сообщения-команды, в хронологическом порядке. Команды и помеченные ответы анализатора исключаются.
2. По умолчанию вся доступная текстовая история передаётся GPT-5.1 **одним запросом**, без конспектов и скрытой обрезки. `ANALYSIS_STRATEGY=single`.
3. До первого платного запроса считаются весь вход, схема ответа и резерв выхода (включая reasoning). Если полный запрос не помещается в контекст, токены или бюджет, анализ не начинается.
4. Проверенный итог сохраняется в закрытом кэше. Неизменившийся диалог с той же целью и настройками берётся из кэша бесплатно. Модель и способ обработки входят в ключ кэша.
5. Старый режим по частям доступен только явно: `ANALYSIS_STRATEGY=hierarchical`. Автоматического переключения или платного повтора нет.

По умолчанию: **GPT-5.1**, `reasoning_effort=low`, до **$0.25** и **180000 суммарных токенов на запуск**. Резерв ответа — 8000 токенов, включая внутреннее рассуждение; вход — до 170000. Тариф: $1.25/1M входных и $10/1M выходных токенов; возможная скидка провайдера не вычитается из консервативной оценки. [Модель и тариф OpenAI](https://developers.openai.com/api/docs/models/gpt-5.1). Поддержаны также GPT-4.1 ($2/$8) и GPT-4.1 mini ($0.40/$1.60). В режиме single модель возвращает только ID свидетельств. Точный текст подставляется программой из оригинала; у длинного сообщения явно помечается начало (до 180 символов). Несуществующие ID и ссылки на нетекстовые вложения отклоняются. Это проверяет источник, но не гарантирует правильность интерпретации.

Если вся история не укладывается, платные запросы не запускаются: в ответе будет оценка и лимит. Можно сознательно запросить `анализ 500` либо поднять лимиты в `.env`. После сетевой ошибки неудачный запрос мог быть тарифицирован провайдером; автоматического повторения нет.

### Что недоступно

Голосовые, фото, видео и файлы **не скачиваются и не распознаются**; учитываются лишь подписи и факт вложения. Удалённые сообщения, звонки, офлайн-общение и внутренние мотивы людей неизвестны. Старые непомеченные AI-ответы из прежней версии не всегда можно отличить от обычного текста. Удалять историю скрипт не пытается.

## Остальные команды

```text
анализ
анализ 100
/question О чём мы договорились? number:100
/question Как менялось общение? number:all
/analysis_help
```

`анализ` и `/question` без `number:` используют `MESSAGE_LIMIT` (50 по умолчанию). Алиасы полного режима: `/super`, `/superanalysis`. Для фокуса нужен разделитель `:`. Обычная фраза «анализ отношений важен» ничего не запускает.

## Установка и запуск

Нужны Node.js 20+ и собственные Telegram API credentials.

```sh
npm ci
cp env.example.txt .env
chmod 600 .env
npm start
```

Заполни `.env` локально на сервере. Первый вход попросит телефон, код и, если включён, пароль 2FA. Пароль и код вводятся скрыто. Сессия сохраняется в `.telegram-session` с правами `600`; в консоль не выводится.

Для конкретных собеседников:

```sh
node index.js username1,username2
```

Фоновый запуск:

```sh
tmux new-session -d -s telegram-helper -c /home/alex/.openclaw/workspace/projects/telegram-helper 'node index.js'
tmux attach -t telegram-helper
```

Отсоединиться: Ctrl+B, затем D. Остановить: Ctrl+C внутри tmux. `tmux` переживает отключение SSH, **не перезагрузку сервера**. Второй экземпляр нового скрипта защищён PID-блокировкой.

Команды с телефона работают и сразу после перезапуска: перед ответом скрипт получает полноценный адрес чата из данных события или списка диалогов. Если начальное сообщение не удалось отправить, история и AI не запускаются; безопасный код ошибки сохраняется в `status.json`, без повторной отправки вслепую.

## Данные на сервере

- `.env`, `.telegram-session` — учётные данные, не входят в Git.
- `.analysis-cache/` — конспекты и отчёты, права каталога `700`, файлов `600`. Содержит приватные производные от переписки, доступные владельцу сервера.
- `.analysis-cache/status.json` — состояние процесса без текста чатов и ключей.
- `.analysis-cache/delivery.json` — ID служебных сообщений и обработанных команд, без содержимого.

В OpenAI отправляются тексты для запрошенного анализа с `store:false`; это не утверждение об отсутствии всех технических журналов провайдера. Полные запросы, ответы, ключи и сообщения не выводятся в логи скрипта.
